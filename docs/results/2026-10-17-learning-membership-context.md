# Signed Network identity for explicit learning consent

Source/local only. This read establishes the Network person/app/member behind an existing admitted turn. It does not grant Google access, save consent, collect data, change a profile, or establish the separate Cloud user/session identity. Cloud owns its independent current private owner/DO checks and exact explicit scope confirmation before its existing primary preference writer.

`POST /internal/profile-suggestions/consent-context` uses the existing service HMAC, no new signer or schema. Canonical `learning-consent-context.ts` is copied unchanged from Auth, SHA-256 `03f2b830dcf41b4b3f66e716cc5fdfef224f7ff103a821557cdbc946615e030b`. The request is exactly `{version:1,purpose:"network_profile_learning_v1",review,selectionSha256}`. The existing review must name a collect action. Caller person IDs, Cloud IDs and owner-proof envelopes are refused.

The endpoint derives the person from the stored signed OPEN turn's sender hash and canonical Network member/app. It verifies the exact stored `collect <batch UUID>` command and digest, current isolated route, signed-parent age, active adult member/person, membership, ban/suppression/phone holds and STOP ledger. Person/member/turn reads use the existing lock order. More than one phone identity fails closed rather than guessing which number owns the STOP ledger. Consent events can append without a person lock, so the endpoint rechecks the ledger after asynchronous signing and describes the result as a fresh bounded observation, not serialization of future changes.

The signed identity-only response binds request hash, nonce, selection digest, exact command/turn and route to the server-derived person/app/member. It returns no phone, profile, Cloud user/org/chat or source content. Lifetime is at most 30 seconds, capped by current route admission and the parent's five-minute lifetime; future/stale parents and post-sign expired authority deny. Repeating a read can produce another nonce-bound observation; Cloud's consent writer separately owns consumption/replay/withdrawal semantics. The operation does not require already-existing learning consent, avoiding a circular bootstrap requirement.

Pinned Bun 1.4.2 and isolated real PostgreSQL on port 54428: four membership HTTP tests passed 33 assertions, including signed proof verification, nonce/selection mismatch, foreign app/member/turn/person association, caller identity rejection, STOP, ambiguous phone identities, bans, holds, minors, removed membership, stale/future parent, and near-expiry parent/route caps. The backend routing suite passed 29 tests and 264 assertions. TypeScript passed. Independent source review found the phone-selection ambiguity and verified the fail-closed correction.

Auth separately reported a paired actual Cloud DO/private handler/primary SQL preference writer joined to this actual endpoint; its receipt is tracked separately and is not a real account/consent/provider claim. The live consent UI, actual Google retrieval/extraction, hosted release and original-account iMessage history acceptance remain open. No new normal build, large worktree, provider request or production mutation was performed for this change.
