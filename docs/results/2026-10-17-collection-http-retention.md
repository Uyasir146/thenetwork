# Authenticated private collection endpoint and retention

Source/local only. `POST /internal/profile-suggestions/collect` joins the existing service HMAC, current signed turn, Cloud owner/source proof callbacks and replay-safe pending store. Default review activation remains off. No consent record, Google request, extraction job, matching input, public MCP tool, schema or deployment is created by this change.

The exact body is `{channel,messageId,batchId,text,proposal,networkAuthority?}`. `text` must be the canonical stored human command `collect <batch UUID>`. `proposal` contains only the explicit window, timezone, pending expiry, retention choice, allowed fields and at most ten minimal source-aware suggestions. Strict keys reject owner fields and raw source objects. Values with control characters or newlines are rejected before persistence, because they cannot form a valid review preview. The backend forwards only this exact additional path under the existing 16 KiB cap.

Network resolves identity and source permission inside the same SQL transaction that creates the batch and completed replay receipt. The factory permits a `collect` context only after the canonical Cloud owner proof; it never derives identity from a proposal. The source proof attests the entire scope and signed `pendingExpiresAt`. The requested proposal expiry must be future and no later than that actual approved deadline. The short proof deadline is independently enforced through all writes and the final transaction check. Replay and deletion behavior use the preceding collection-store change.

Canonical mirrors are copied byte-for-byte from Auth's separate collection successor: owner contract SHA-256 `a7ee8cff5a6984bb1a99a5936deba903b61c119472826da9e8105c81a35e690d` adds `collect`; source contract SHA-256 `6c222fe26d0120edf3d8de4b0b451845004481fc48361d3e51b8ca5a96351089` requires the signed pending-retention deadline. Older qualified Cloud source remains frozen. Missing new fields deny; no unlimited-retention fallback exists.
